# 무료 정비 기록과 재구매 수요 검증

기본 차량 관리와 알림은 무료로 제공한다. 사용자가 전에 구매한 제품을 교체 시점에
다시 찾는 수요가 있는지 확인한 후 외부 판매처와 제휴하는 것을 목표로 한다.
현재 버전에는 결제, 제휴 계약, 구매 전환 확인, 수수료 정산이 없다.

## 구현한 사용자 흐름

1. 소모품 등록 시 제품명과 구매 URL을 선택적으로 저장한다. 기존 소모품도 링크 추가/수정/삭제가 가능하다.
2. 소모품 카드의 `지난번 제품 다시 보기`로 저장된 외부 상품 페이지를 새 창에서 연다.
3. 차량 카드에서 현재 주행거리를 갱신하면 전체 소모품 상태가 다시 계산된다.
4. 같은 제품으로 교체한 뒤 실제 날짜와 주행거리를 기록한다. 이전 기록은 이력에 남고 다음 주기가 갱신된다.

링크는 사용자가 저장한 주소이며, DriveCare가 규격이나 호환성을 검증한 추천이 아니다.
외부 사이트에서 가격과 규격을 확인하도록 안내한다. 제휴 광고나 할인으로 표시하지 않는다.
다른 제품으로 변경하는 기능과 소모품 관리 종료는 후속 작업이다.

## 측정 항목과 한계

- `usage_visits`: 로그인 또는 로그인된 상태에서 앱을 열 때의 활동. 60초 자동 조회는 제외한다.
- `repurchase_clicks`: 소모품 ID, 로그인 사용자 ID, 판매처 호스트, 당시 정비 상태, 클릭 시각.
- `maintenance_replacements`: 최초 기록과 이후 교체 기록의 제품·주기·날짜·주행거리 스냅샷.
- [조회 SQL](../scripts/repurchase-metrics.sql): 링크 저장 수, 일별 클릭 수/클릭 사용자 수,
  일별 활동 사용자 수, 둘 이상의 날짜에 방문한 사용자 수, 반복 교체 기록 수.

측정은 로그인한 사용자의 서비스 내 활동에 한정하며 제3자 분석 도구로 전송하지 않는다.
제공된 조회 SQL에는 테스트 계정도 포함되므로 실제 사업 검증 시 테스트 계정을 제외한 결과를 사용해야 한다.
클릭 집계 실패가 판매처 이동을 막지 않도록 처리한다. 이 때문에 네트워크 오류 시 일부 클릭이 누락될 수 있다.
반복 클릭은 별도 이벤트다. 클릭은 구매도, 판매처 페이지 로딩 성공의 증거도 아니다.
노출 수를 수집하지 않으므로 클릭률(CTR)은 계산하지 않는다. 현재 재방문 사용자 수는
관찰 기간의 활동 지표이며 D7/D30 코호트 유지율이 아니다. 실제 운영 시 개인정보 안내에 활동 수집과 보관 정책을 포함한다.

운영자가 로컬 터미널에서 집계할 때:

```powershell
Get-Content scripts/repurchase-metrics.sql -Raw | docker compose exec -T mariadb sh -c 'exec mariadb -u"$MARIADB_USER" -p"$MARIADB_PASSWORD" "$MARIADB_DATABASE"'
```

## 구현과 데이터 보호

- Flyway V2가 구매 URL/수정 버전, 교체 이력, 클릭/방문 테이블을 추가하고 기존 교체 기록을 이력으로 보존한다.
- 모든 새 API에 로그인과 소유권 검사를 적용하며 변경 요청에는 CSRF 토큰이 필요하다.
- 구매 URL은 HTTP(S) 주소만 허용하고 사용자 정보가 포함된 URL은 거부한다. 서버는 해당 주소에 접속하지 않는다.
- 교체 완료는 트랜잭션 안에서 이력 추가·최근 교체일 갱신·기존 알림 읽음 처리를 수행한다.
- 수정 버전 검사와 행 잠금으로 이전 화면에서의 중복 제출을 거부한다.
- 미래 교체일, 이전 기록보다 과거인 날짜/주행거리, 현재 차량 주행거리보다 큰 값은 거부한다.

## 다음 사업 검증

실사용자를 대상으로 교체 기록을 계속 유지하는지와 재구매 링크를 사용하는지 먼저 관찰한다.
그 후 해당 판매처의 제휴 조건과 전환 확인 방식을 확보한다. 계약 전에는 임의의 수수료율,
예상 매출, 구매 성공 수를 화면에 표시하지 않는다.
