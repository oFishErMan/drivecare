# DriveCare 제품 개선 사이클

## 2026-11-04 · 01 차량 단위 교체 이력과 내보내기

대상은 계기판 값과 교체 기록을 직접 관리하는 개인 운전자다. 공식 제품 문서에서 확인한 기능 비교이며, 제품 직접 사용, 고객 인터뷰, 수요 측정은 수행하지 않았다.

### 문제와 우선순위

- 기존: 교체 기록은 저장되지만 소모품별 카드에서 따로 확인해야 한다. 관리 종료된 항목의 기록도 DB에는 남지만 카드에서 찾을 수 없다.
- 가설: 차량 관리에서 최신 교체 기록을 바로 열고 파일을 받을 수 있으면, 과거 정비 확인·백업을 위해 여러 화면을 오갈 필요가 줄어든다.
- 이번 선택: 차량 단위 이력 조회와 CSV. 기존 기록을 활용해 스키마 변경 없이 제공할 수 있다.
- 다음 후보: (1) 거리 입력이 오래된 차량에 갱신 안내를 제공해 알림 판단 근거를 보여주기 (2) 실제 사용에서 이력이 길어지면 기간 필터와 내보내기 범위 추가 (3) 수요 확인 후 정비 영수증 첨부 검토. 알림 채널 확대, 외부 데이터 연동은 보안·운영 비용 때문에 보류한다.

### 수용 기준

1. 차량 관리에서 선택 차량의 교체 기록을 날짜 내림차순으로 조회한다. 같은 날짜는 기록 ID 내림차순으로 정렬하고, 20건씩 표시한다.
2. 관리 종료한 소모품은 과거 기록을 유지하되 현재 상태를 명시한다. 구매 URL·이메일·다른 차량의 이력은 결과에 넣지 않는다.
3. 본인 차량에만 조회·다운로드를 허용한다. 미인증은 401, 다른 계정과 존재하지 않는 차량은 404로 응답한다.
4. CSV는 UTF-8 BOM을 사용한다. 제품명의 쉼표·따옴표는 이스케이프하고 수식처럼 시작하는 값은 CSV 출력에서만 텍스트 표식을 붙인다. [OWASP CSV Injection](https://owasp.org/www-community/attacks/CSV_Injection) 참고. 원본 DB 값은 바꾸지 않는다.
5. 파일은 요청 시 생성하며 서버에 보관하지 않는다. 5,000건을 넘기면 422로 안내하고 파일을 조용히 잘라 제공하지 않는다. 파일은 자체 입력한 기록이며 공식 정비 증명서가 아니다.

### 검증과 다음 관찰

- 2026-11-04 실행: 백엔드 회귀 36개, 실제 인프라 통합 4개, 프런트엔드 37개 통과. 린트와 프로덕션 빌드 통과.
- 브라우저 가상 데이터 검수: 관리 종료 표시, 빈 이력, 오류 재시도, CSV 다운로드, ESC 이후 원래 버튼 포커스 복원.
- JUnit/MockMvc: 차량 간 격리, 정렬·페이지 경계, 빈 이력, 관리 종료, 권한, CSV 헤더와 필드.
- JUnit 단위 테스트: 수식 유사 문자열의 텍스트 표식과 다운로드 상한.
- Testcontainers: MariaDB에서 관리 종료 이력 조회·CSV 출력.
- 프런트엔드: CSV 응답 유형·오류 처리 자동 테스트, 차량 관리에서 정상·빈 이력·실패 표시를 검수할 수 있는 읽기 전용 픽스처.
- 이후 사용자 검증: 첫 방문과 재방문 각각에서 과거 교체일을 찾아 CSV를 받는 과제를 관찰한다. 소요 시간·화면 이동 횟수·혼동한 문구를 기록한다. 이번 사이클에서 사용성 개선 수치를 측정했다고 주장하지 않는다.

### 범위 및 운영

- 읽기 API: `GET /api/vehicles/{id}/history?page=0`, `GET /api/vehicles/{id}/history/export`. 페이지 번호는 0부터 시작한다.
- 조회와 내보내기 모두 차량과 소유자 조건을 함께 사용한다. 목록은 offset 기반이며, 페이지 이동 중 새 기록이 저장되면 행 위치가 달라질 수 있다.
- 5,000건 상한은 단일 요청 메모리를 제한하기 위한 값이다. 대규모 데이터 이전과 포맷 재가져오기는 보장하지 않는다.
- 배포 순서: 백엔드 먼저, 프런트엔드 다음. 기존 API·스키마 변경 없음. 서비스 컨테이너만 이전 이미지로 되돌릴 수 있다.

### 로컬 릴리스 기록

- 앱 컨테이너 두 개만 교체했다. MariaDB·Redis 컨테이너 ID는 이전과 동일했다.
- 로컬 배포에서 새 UI 번들과 OpenAPI의 이력 경로 2개, 미인증 요청의 401을 확인했다. 이력의 정상 데이터와 소유권은 MockMvc·격리된 MariaDB 테스트에서 검증했다.
- 변경 전 소스 `f409f25`로 복구용 이미지를 별도 빌드했다. 현재 로컬에 아래 태그가 남아 있을 때 앱만 되돌릴 수 있다. DB와 Redis는 건드리지 않는다.

```powershell
docker image tag drivecare-backend:rollback-history-20261104 drivecare-backend:latest
docker image tag drivecare-frontend:rollback-history-20261104 drivecare-frontend:latest
docker compose up -d --no-deps --wait backend
docker compose up -d --no-deps --wait frontend
```

## 2026-11-04 · 02 주행거리 판단 근거 표시

### 발견과 결정

- [Drivvo 공식 FAQ](https://www.drivvo.com/en/faq/)는 계기판 기반 교체 알림과 주기적 주행거리 기록을 안내하고, [마이클 정비 기록 안내](https://mycle.co.kr/post/tip/contents_onboarding-record_260615.html)는 주행거리와 과거 교체 기록을 판단 근거로 설명한다.
- DriveCare의 문제는 거리 계산 자체가 아니라 **계기판 값을 언제 관측했는지 사용자에게 보이지 않는 것**이다. 최근 입력을 유도하되 임의 보간·자동 갱신·새 알림 채널은 추가하지 않는다.
- 30일은 정비 권고가 아닌 UI 안내 기준이다. 기간 주기·정비 상태 코드·기존 알림 스케줄러는 변경하지 않는다.

### 수용 기준

1. 차량 카드에 현재 누적거리와 일치하는 가장 최근 측정일과 경과일을 표시한다. 새로운 날짜의 낮은 값이나 미래의 기존 데이터로 현재 값이 최근인 것처럼 보이지 않게 한다.
2. 서버 업무 시간대의 달력 날짜로 29일 이하는 최근, 30일 이상은 확인 필요, 일치하는 유효 기록이 없으면 측정일 확인 불가로 분류한다. 같은 계기판 값을 오늘 다시 확인한 경우에도 오늘로 갱신할 수 있다.
3. 정비 현황에서는 화면에 표시된 거리 기준 항목의 해당 차량만 한 번씩 안내하고, 차량 관리로 이동시킨다. 기간 전용 항목은 거리 기록 때문에 경고하지 않는다.
4. UI의 오늘 기록은 브라우저 시간대를 보내지 않는다. API는 날짜 생략 시 서버 업무 날짜를 쓰고, 명시적으로 보낸 미래 날짜는 400으로 거절한다. 기존 거리 역행 금지와 소유권 잠금은 유지한다.

### 구현과 한계

- 차량 목록은 차량 및 현재 거리와 일치하는 측정일을 같은 조회문에서 읽는다. 새 테이블·마이그레이션·백필은 없다.
- 조회 응답에 `odometerFreshness` (측정일, 경과일, 상태)를 추가한다. 과거 기록을 수정하거나 현재 주행거리를 추정하지 않는다. 기록의 실제 계기판 정확성은 운전자 입력에 의존한다.
- 다음 검증 후보: 파일럿에서 경고를 이해하고 갱신까지 도달하는지 관찰한 뒤 30일 기준을 재검토한다. 정비 지표 개선이나 실제 사용자 반응은 아직 측정하지 않았다.

### 검증 및 로컬 릴리스

- 백엔드 `test integrationTest --rerun-tasks`: 회귀 42개, Testcontainers 5개 통과(실패·오류·건너뜀 0). 29/30일 경계, 서울 자정, 과거 날짜의 큰 값, 미래·누락 값 거부, 동일 거리 재확인을 검사했다. MariaDB에서 현재 값과 일치하는 측정일을 재조회했다.
- 프런트엔드 `pnpm lint`, `pnpm test` 40개, `pnpm build` 통과. 가상 데이터 브라우저에서 차량별 안내, 차량 관리 이동, 기간 전용 검색 시 경고 제외, 날짜 불명 표시 및 CSV·키보드 동작을 확인했다.
- Compose에서 백엔드·프런트엔드만 교체했다. OpenAPI의 `odometerFreshness`와 이력 API, 최신 번들, 미인증 401을 확인했다. 기존 MariaDB·Redis 컨테이너 ID는 그대로이며 사용자 기록을 테스트로 쓰지 않았다.
- 1차 기능 상태로 되돌릴 때는 `drivecare-backend:rollback-freshness-20261104`, `drivecare-frontend:rollback-freshness-20261104` 태그를 각각 `:latest`로 지정하고 앱 서비스만 재생성한다.
- 사용성 효과, 부하 재측정, 공개 배포는 이번 검증 범위가 아니다.
