# 데이터 정합성 및 100명 동시접속 테스트

실행일: 2026-10-05 22:00~22:02 KST. 로컬 Docker Compose 환경에서 실제 HTTP API를 호출했습니다. 부하 발생기와 서버가 같은 PC를 사용합니다.

## 판정

100명 동시접속 스트레스 테스트는 **실패**입니다. 빠른 응답만으로 통과로 판정하지 않습니다. 502 응답과 미래 교체일 검증 누락이 발견되었습니다.

## 생성한 데이터

- 전용 계정 100개, 계정별 차량 1대, 소모품 7개: 차량 100대 / 소모품 700개
- 미래 교체일 검증 요청이 잘못 수락되어 추가 소모품 1개가 존재합니다.
- 이메일: `loadtest-20261005130042-001@example.test` ~ `loadtest-20261005130042-100@example.test`
- 테스트 계정 공통 비밀번호: `LoadTest1234!` (로컬 테스트 전용)
- 원래 `test@drivecare.local` 계정의 차량·소모품 값은 테스트 전후 동일합니다.
- 테스트 데이터는 결과 확인을 위해 DB에 유지했습니다.

## 테스트 방법

실제 CSRF 토큰과 쿠키를 사용합니다. 100명이 각각 로그인한 독립 Redis 세션으로 약 45초간 반복 접속했습니다. 각 사용자는 내 계정, 차량, 소모품, 알림을 순서대로 조회하고 5회 반복마다 주행거리를 저장합니다. 반복 사이 대기 시간은 200ms입니다. 단순히 TCP 연결 100개를 열어두는 테스트가 아닙니다.

로그인 동시 요청과, 한 차량의 같은 날짜에 100개의 서로 다른 주행거리를 동시에 저장하는 경합 테스트를 별도로 실행했습니다. 경합에서 뒤늦게 들어온 작은 주행거리의 400 응답은 정상 거부로 처리했습니다. 일반 부하 단계에서는 모든 요청이 200이어야 합니다.

## 정합성 검사

- 정상 / 임박 경계(1,001km, 1,000km) / 교체 시점(0km) / 5,100km 초과 / 기간 도달 / 30일 임박 계산: 통과
- 다른 계정 차량에 주행거리 저장 또는 소모품 등록: 404로 차단
- 주행거리 감소, 음수, 현재보다 큰 교체 당시 거리, 누락된 교체주기: 400으로 차단
- 같은 차량 100개 동시 저장: 가장 큰 값 120,100km 보존
- 같은 차량·날짜 주행기록: 중복 없음
- DB 고아 차량·소모품, 중복 이메일·주행기록·알림, 차량 누적거리와 기록 최대값 불일치, 음수 거리, 잘못된 교체거리, 알림 소유자 불일치: 모두 0건
- Redis 세션 키 201개 확인 (준비 단계와 부하 단계 로그인 세션 포함), 표본 TTL 약 1,703초
- 기존 데모 데이터 보존: 통과
- 기존 백엔드 테스트를 캐시 없이 재실행: 단위 테스트 5개와 실제 MariaDB·Redis 통합 테스트 1개 모두 통과 (`gradlew test integrationTest --rerun-tasks`, 7개 작업 실행)

## 발견한 문제

1. Nginx → 백엔드 연결에서 `connect() ... failed (99: Address not available)`가 반복되었습니다. 백엔드 OOM이나 재시작은 없었습니다. 현 프록시 설정은 upstream keepalive 풀과 Connection 헤더 정리가 없어 요청마다 새 연결이 만들어질 수 있습니다. 빠른 반복 요청으로 임시 포트가 소진된 것으로 판단합니다. upstream 연결 재사용을 적용하고 같은 조건으로 재검증해야 합니다.
2. 미래 날짜의 교체 기록을 서버 API가 201로 허용합니다. 프런트엔드 날짜 제한만 있고 서버 요청에는 미래일 제한이 없습니다. 서버 검증을 추가해야 합니다.

이번 요청은 테스트 수행이므로 위 애플리케이션·프록시 문제를 수정하지 않았습니다.
