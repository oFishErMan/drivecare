# 사용 흐름 중심 기획·개발 지시서

## 작업 방식

기획자 역할에서 문제와 완료 조건을 정하고, 같은 작업 안에서 개발자 역할로 구현·검수한다.
별도의 외부 인력에게 발송하거나 실제 사용자 조사를 수행한 것은 아니다. 기존 화면과 구현 계약에 근거한 판단이다.

## 목표

사용자가 차량의 관리 상태를 이해하고, 정확한 교체 기준을 입력하며, 중복 소모품 생성 대신 기존 기록을 갱신할 수 있게 한다.
기능 수 확대보다 기존 차량 → 소모품 → 정비 기록의 연결을 우선한다.

| ID | 문제 / 왜 필요한가 | 개발 지시 / 완료 조건 |
| --- | --- | --- |
| FLOW-01 | 차량 관리에는 주행거리만 있어 차량별 정비 필요 여부를 확인하려면 다른 탭에서 다시 찾음 | 차량별 전체·교체 필요·임박 수와 상태 보기 버튼. 선택 차량으로 필터 초기화 후 정비 탭 진입. 소모품 0개를 정상으로 표현하지 않음 |
| FLOW-02 | 등록 입력이 다음 교체 기준으로 어떻게 변환되는지 저장 후에야 알 수 있음 | 등록 옆에 입력 기준 미리보기. 거리 공식·기간 계산 근거·빈 값 안내. 월말/윤년은 서버 plusMonths와 동일하게 보정. 최종 상태는 서버 계산임을 명시 |
| FLOW-03 | 동일 차량·종류를 다시 등록하면 교체 이력이 분산될 수 있음 | 기존 동일 종류 개수와 보기 행동 제공. 중복을 금지하지 않고 타이어 등 여러 항목을 구분 등록할 수 있음을 안내. 미저장 작성은 유지 |
| FLOW-04 | 오늘 교체한 기록도 날짜·주행거리를 두 번 입력해야 함 | 명시적 '오늘 · 현재 주행거리로 입력' 버튼. 실제 교체 사실은 추정하지 않으며 자동 적용하지 않음 |
| FLOW-05 | 주행거리 갱신은 입력만 있고 기존 값과의 차이·저장 영향이 보이지 않음 | 이전 값 → 입력 값 및 증가 거리 표시. 감소 입력은 필드에서 차단, 계기판 누적 거리임을 설명. 저장 후 소모품 재계산 설명 |
| FLOW-06 | 서버 필드 오류 후 수정해도 같은 오류가 남고 접힌 구매 링크 오류를 찾기 어려움 | 해당 입력 수정 시 그 필드 오류 정리. 오류가 선택 상세에 있으면 펼친 후 포커스. API 저장 결과를 완료 콜백에 전달하여 이후 확장 시 재조회로 생성 대상을 추측하지 않음 |
| FLOW-07 | 긴 소모품 폼을 읽는 중 계산 결과·제출 위치를 잃기 쉬움 | 데스크톱 폼+미리보기 2열, 작은 화면은 단일 열. 폼 아래 제출 유지. 미리보기는 보조 영역으로 식별하고 좁은 화면 넘침 없음 |
| FLOW-08 | 교체 당시 주행거리가 현재 기록보다 크면 갱신해야 하나, 화면을 찾아 이동해야 함 | 등록·교체 기록에서 해당 차량 주행거리 관리로 바로 이동. 작성 중인 입력은 유지 |

## 범위에서 제외

- 자동으로 권장 교체주기를 채우거나 차량 안전 상태를 보증하지 않는다.
- 차량 삭제·매각, 제품 변경 시 이력 통합, 실제 Web Push는 정책을 정한 뒤 별도 개발한다.
- 신규 인프라·과금·외부 전송·비즈니스 데이터 삭제는 하지 않는다.
- 실사용자 지표가 없으므로 전환율이나 사용성 개선 수치를 성과로 주장하지 않는다.

## QA 지시

순수 계산은 자동 테스트로 빈 값·0·초과·월말·윤년·정수 범위를 확인한다. 브라우저에서는 차량별 연결, 입력 미리보기,
동일 종류 안내, 탭 이동 후 초안 유지, 모바일 가로 넘침, 기존 등록 패널, 오류 로그를 확인한다.
기존 운영 테스트 계정의 차량·교체 기록은 변경하지 않고 입력 검증은 저장 전 상태로 수행한다.

## 구현·검수 결과

### 완료

- FLOW-01~08 구현. 차량 카드별 관리/필요/임박 수와 정확한 차량·종류 조회 연결 제공.
- 소모품 등록에 거리·기간 계산, 필수 입력 진행률, 남은 입력 안내, 기존 항목 안내, 오늘 기록 입력, 주행거리 관리 바로가기 추가.
- 입력 수정 시 해당 서버 필드 오류 정리, 접힌 상세 오류 펼침/포커스, 빠른 입력 후 오래된 브라우저 유효성 오류 제거.
- 공통 저장 훅에 동기 중복 요청 가드 추가. 저장 성공 이후 화면 갱신 실패를 저장 실패로 오인하지 않도록 구분.
- 계산을 `domain/registrationPreview.js`, 조회를 `domain/maintenanceView.js`, 보조 화면을 `RegistrationPreview`, 시각 규칙을 `journey.css`로 분리.
- Docker 없이 검수할 수 있는 `frontend/qa` 추가. 가상 데이터임을 명시하며 모든 저장 요청을 거절하고 프로덕션 빌드에서는 제외.

### 검증

- 프런트엔드 테스트 35개, lint, 프로덕션 빌드 통과.
- 백엔드 테스트 30개 통과(실패/건너뜀 0). H2 메모리 DB 사용. 월말·윤년의 서버 기간 계산 회귀 테스트 추가.
- 가상 데이터 화면: 차량 2대의 상태 요약/소모품 없는 차량, 해당 차량·종류 필터, 탭 이동 후 초안 유지, 360px 가로 넘침 없음 확인.
- 가상 오류 응답: 저장 중 입력 비활성화, 오류 후 값 유지, 접힌 구매 링크 자동 열기와 첫 오류 포커스, 수정 후 오류 해제 확인.
- 현재보다 큰 교체 주행거리의 제출 차단 및 빠른 입력 후 native 유효성 복구 확인.
- Docker 중지 원인은 WSL 업그레이드 마무리 대기였으며, 설치 프로세스 종료 확인 후 Docker 정상 재시작으로 복구. 볼륨 초기화나 데이터 삭제 없음.
- 실제 프런트엔드 Docker 이미지 재빌드·배포 완료. MariaDB/Redis/백엔드 healthy 확인.
- 실제 `localhost:3000`에서 차량별 요약, 등록 항목 안내, 113,000+8,000=121,000km 및 현재 120,100km 대비 900km 남음 미리보기 확인. 최종 브라우저 오류 로그 없음.
- 이번 실제 화면 검수에서는 차량·소모품을 새로 저장하거나 교체 기록을 수정하지 않음. 방문 통계 등 기존 자동 요청은 그대로 동작.

### 범위와 후속

- UI 가상 오류 테스트와 실제 DB 저장 통합 검증은 구분한다. 이번에 MariaDB/Redis 통합 테스트·100명 부하 테스트를 새로 실행한 것은 아니다.
- 프런트엔드 미리보기는 저장 상태의 권위가 아니며, 실제 상태/알림 판단은 기존 서버 계산을 유지한다.
- 실제 사용자 조사를 수행하지 않았으므로 전환율·사용성 개선 수치를 주장하지 않는다.
- 신규 인프라나 과금 없이 기존 사용 흐름의 정보·행동·실패 회복을 개선했다는 점을 포트폴리오에서 설명할 수 있다.
